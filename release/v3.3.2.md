# NekoKEM v3.3.2

## 简体中文

### 本版更新

v3.3.2 为桌面 GUI 和 Android 增加公钥通讯录，并为 Android 加入预测性返回。Android 与所有 CLI/GUI 应用统一为 3.3.2，Core 保持 3.1。

- **桌面 GUI 公钥通讯录**：Windows、macOS 和 Linux 共用的 Rust + Tauri 2 + Vue 3 + TypeScript GUI 新增“公钥通讯录”页面，可从文件或粘贴内容保存接收方公钥，添加、编辑备注，确认后删除；加密页可直接选择已保存的联系人。相同指纹只保存一次，列表显示完整 SHA-256 指纹。
- **每次使用都重新校验**：条目保存在语言设置旁的私有 `contacts` 目录（Windows 为 LocalAppData，macOS/Linux 为 `$XDG_CONFIG_HOME` 或 `~/.config`），权限为仅所有者。每次加密都会重新读取条目，并由现有 Core 校验公钥与指纹；条目缺失、损坏、权限异常或指纹不符时报错并要求重新选择，**绝不会改用其他公钥**。重新导入同一公钥可修复指纹不符的条目。
- **限制与清理**：最多 500 个联系人，备注最多 512 个字符（按 Unicode 码点计数），名称剔除双向控制字符；公钥和记录大小均有上限。五种界面语言同步更新，密码参数、文件格式和秘密清理机制不变。
- **Android 公钥通讯录修复**：备注长度改按 Unicode 码点计数（此前按 UTF-16 单元，表情符号会被少算空间），保存的文件名剔除双向控制字符。
- **Android 预测性返回**：启用 `enableOnBackInvokedCallback`。在密钥管理、公钥通讯录、设置、关于页面侧滑返回时，页面随手指缩小、平移并显示圆角，下方预览文件加密页；松手返回，取消则复原。侧边菜单随手势关闭，不会退出 App；文件页仍由系统显示返回桌面动画。Android 14 及以上有跟手进度，更早版本直接返回。
- **测试**：新增桌面通讯录的 Rust 单元测试、前端测试与窗口测试，新增 Android 预测性返回设备测试，并在 API 26/35 上保存手势截图；CI 全平台通过。

### Android 升级

Android 应用为 **3.3.2 / versionCode 7**，最低 API 26，目标 API 35，仅提供 arm64-v8a。**沿用 v3.2.0/v3.3.0 发布签名，可直接覆盖升级，无需卸载。** 建议先导出公钥和加密 NKPR 私钥，验证备份并保留私钥密码。

仅旧签名 v3.1.x 用户需要在备份验证后卸载重装；卸载会删除内部密钥与数据，没有可用私钥或忘记密码将无法恢复解密。指纹不能恢复密钥。历史签名迁移见 [v3.2.0](https://github.com/Shixiaoshi0417/NekoKEM/blob/main/release/v3.2.0.md)。

### 格式、安全边界与兼容性

- **Core 3.1、NKEM v3、NKPR v1 不变**。X448 + ML-KEM-1024、HKDF-SHA512、AES-256-GCM、header/AAD、KDF 输入与 domain、nonce/tag、指纹与 GCM 长度限制保持原有要求。NKEM v1/v2 不再支持。
- NKPR 仍使用 Argon2id **64 MiB、3 次迭代、并行度 4**，不降低密码成本；随机性、认证、敏感缓冲区清理和认证后提交规则保持不变。
- Windows 10/11 x64 保留本地固定 NTFS、所有者/ACL/可信父目录检查，以及网络、设备、ADS、重解析点拒绝。Windows CLI/GUI **没有 Authenticode 签名**；验证 Microsoft SDK loader 不代表应用已签名。GUI 需要 WebView2 Runtime。
- macOS 面向原生 M 系列 arm64，不提供 Intel/Rosetta 包。部署目标为 macOS 11.0，实际原生验证于 macOS 15；不等同于已验证 macOS 11.0 实机或每代芯片。包使用 **ad-hoc hardened-runtime 签名，没有 Developer ID 和 Apple 公证**，不能证明发布者身份或保证 Gatekeeper 放行。
- Linux GUI 构建基线为 Ubuntu 24.04，RPM 另在 Fedora 44 原生容器验证。需要 glibc 2.39+、GTK3 和 WebKitGTK 4.1；RPM 没有开发者 GPG 签名。X11 窗口检查不代表所有发行版或 Wayland 实机兼容。静态 Linux CLI 包继续提供。
- GUI 的 JavaScript/IPC 可能产生临时字符串副本，不能保证 WebView 堆可靠清零。成对文件提交不具备跨文件崩溃原子性；Windows 断电持久性、进程死亡、真实 SAF provider、并发修改和物理擦除仍有文档所述边界。不承诺跨系统或硬件性能相同。

本项目仍是实验性工具，**没有经过独立专业安全审计，不应视为生产级软件，不应用于保护重要或敏感数据**。

## English

### What's new

v3.3.2 adds public-key contacts to the desktop GUI and predictive back to Android. Android and every CLI/GUI application are version 3.3.2; Core remains 3.1.

- **Desktop GUI public-key contacts**: the Rust + Tauri 2 + Vue 3 + TypeScript GUI shared by Windows, macOS and Linux gains a Public-key contacts page. Save a recipient's public key from a file or pasted text, add or edit a note, and delete entries after confirmation. The encryption page can choose a saved contact directly. Each fingerprint is stored once and the full SHA-256 fingerprint is shown.
- **Re-validated on every use**: entries live in a private `contacts` directory beside the language preference (LocalAppData on Windows; `$XDG_CONFIG_HOME` or `~/.config` on macOS/Linux), owner-only. Every encryption re-reads the entry and re-validates the public key and fingerprint with the existing Core. Missing, damaged, unsafe-permission or mismatched entries fail and require a new selection; **another public key is never substituted**. Re-importing the same key repairs an entry whose fingerprint mismatches.
- **Limits and cleanup**: up to 500 contacts, notes up to 512 characters (counted in Unicode code points), names stripped of bidirectional control characters, and size caps on keys and records. All five interface languages are updated; cryptographic parameters, file formats and secret clearing are unchanged.
- **Android contacts fixes**: note length is now counted in Unicode code points (previously UTF-16 units, which undercounted emoji), and stored file names strip bidirectional control characters.
- **Android predictive back**: `enableOnBackInvokedCallback` is enabled. Going back from Key management, Public-key contacts, Settings or About makes the page shrink, move and round its corners with the gesture, previewing the Files page beneath; releasing returns, cancelling restores. The navigation drawer closes with the gesture instead of leaving the App; the Files page still shows the system back-to-home animation. Android 14+ provides live progress; earlier releases go straight back.
- **Tests**: new Rust unit tests, frontend tests and window tests for desktop contacts, plus Android predictive-back device tests with a mid-gesture screenshot on API 26/35. CI passes on every platform.

### Updating Android

Android is **3.3.2 / versionCode 7**, minimum API 26, targeting API 35, with arm64-v8a only. **The v3.2.0/v3.3.0 release signer is retained, allowing an in-place update without uninstalling.** Back up the public key and encrypted NKPR private key, verify those backups and retain the private-key password first.

Only old-signer v3.1.x installations need verified backups followed by uninstall/reinstall. Uninstalling deletes private keys and data; without a usable private key or its password, decryption cannot be recovered. Fingerprints cannot restore keys. Historical signing migration is documented in [v3.2.0](https://github.com/Shixiaoshi0417/NekoKEM/blob/main/release/v3.2.0.md).

### Formats, security boundaries and compatibility

- **Core 3.1, NKEM v3 and NKPR v1 are unchanged**. X448 + ML-KEM-1024, HKDF-SHA512, AES-256-GCM, headers/AAD, KDF inputs/domains, nonce/tag, fingerprints and GCM length limits retain their requirements. NKEM v1/v2 are no longer supported.
- NKPR still uses Argon2id with **64 MiB, 3 iterations and parallelism 4**, without reducing password cost. Randomness, authentication, sensitive-buffer cleanup and authenticated output commits retain their requirements.
- Windows 10/11 x64 retains local fixed NTFS, ownership/ACL/trusted-ancestor checks and rejection of network/device/ADS/reparse paths. Windows CLI/GUI are **not Authenticode signed**; verifying the Microsoft SDK loader does not sign the applications. The GUI requires WebView2 Runtime.
- macOS targets native M-series arm64, without Intel/Rosetta packages. The deployment target is macOS 11.0; native verification runs on macOS 15, not physical macOS 11.0 hardware or every chip generation. Packages use **ad-hoc hardened-runtime signatures without Developer ID or Apple notarization**, so they do not authenticate the publisher or guarantee Gatekeeper acceptance.
- Linux GUI builds use Ubuntu 24.04; RPM is additionally verified in native Fedora 44 containers. glibc 2.39+, GTK3 and WebKitGTK 4.1 are required. RPM is not developer GPG signed. X11 checks do not establish compatibility with every distribution or physical Wayland session. Static Linux CLI packages remain available.
- JavaScript/IPC may create temporary string copies, so reliable WebView heap zeroization is not guaranteed. Paired-file commits are not crash atomic across files. Windows power-loss durability, process death, real SAF providers, concurrent modification and physical erasure retain documented limits. Identical performance across systems or hardware is not promised.

This remains experimental software. **It has not undergone an independent professional security audit, must not be considered production-grade, and must not be used to protect important or sensitive data.**
