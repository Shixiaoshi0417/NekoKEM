# NekoKEM v6.0.0

## 简体中文

### 本版更新

本版把私钥改为带密钥承诺的 NKPR v3，并新增 Windows EXE 安装程序、Linux AppImage 和 Flatpak 包。Android 与各平台 CLI/GUI 统一为 **6.0.0**，Core 为 **6.0**；NKEM 文件格式和密码参数不变。

- **私钥改用 NKPR v3**：新生成和升级的私钥写为 NKPR v3，在 NKPR v2 的 salt 之后加入 32 字节密钥承诺，一个私钥文件只能被一个口令打开。NKPR v2 私钥的密钥、口令、公钥和指纹都不变。
- **旧格式私钥只作本机私钥**：NKPR v1、v2 不带密钥承诺，别人可以构造出能被多个口令打开的文件，借你输入口令来试探。因此各端只把自己的私钥当作旧格式打开：Android 是应用内的密钥，桌面 GUI 是设置里的「我的私钥」，CLI 是 `keys/private.key.enc`。自己的 NKPR v2 私钥解锁后原地改写为 NKPR v3，口令不变。
- **导入旧版导出的私钥**：Android 导入旧格式私钥时，输入口令前先说明风险，确认是自己从旧版导出的私钥后才打开；4.x 的 NKPR v1 私钥可以选择立即升级为身份密钥，或在 3 秒警告后按原格式导入。桌面应用的「升级密钥」遇到「我的私钥」以外的旧格式私钥时，先显示警告，3 秒后才能确认，确认后改写为 NKPR v3。临时私钥拒绝旧格式。CLI 只有加上 `--legacy-private-key` 才打开其他路径上的旧格式私钥，`upgrade-key` 把私钥改写为 NKPR v3。
- **导出给 5.2 及更早版本的私钥**：Android 密钥页和桌面应用（「给旧版本 → 给 5.2 的私钥」）新增此操作，CLI 新增 `export-legacy-private-key`，用同一口令导出 NKPR v2 副本，供旧版安装使用。macOS 导出时也可以把口令保存到钥匙串。
- **Windows EXE 安装程序**：新增 `NekoKEM-Windows-GUI.exe`，双击安装，装的是与 MSI 相同的应用；参数原样交给 `msiexec`，`/quiet` 可静默安装。
- **Linux AppImage**：每种架构新增 `NekoKEM-linux-<架构>-GUI.AppImage`，单个文件，`chmod +x` 后直接运行，不需要安装或 root 权限。需要 FUSE（`fusermount3`），没有时加 `--appimage-extract-and-run`。
- **Flatpak**：每种架构新增单文件包 `NekoKEM-linux-<架构>-GUI.flatpak`（应用 ID `io.github.shixiaoshi0417.NekoKEM`，Freedesktop 26.08 运行时）。沙盒不开放任何文件系统权限，文件、密钥和解密目录都通过桌面的文件选择框（xdg-desktop-portal）选择，应用只能访问选中的内容。
- **Arch Linux**：仓库新增 `linux/arch/PKGBUILD`（`nekokem-bin`），把发布的 CLI 与 GUI 便携包打成 pacman 包，x86_64 与 aarch64 都可用。
- **更新提示附上发布说明**：Android 与桌面应用的更新提示带上新版本的发布说明，默认折叠，展开后限高滚动，按界面语言显示对应段落。
- **界面更简洁**：各端去掉页面上常驻的解释性小字，包括关于页简介、通讯录与多选提示、设置开关的副标题、导出旧版密钥按钮下的说明、指纹二维码说明和加密页密码框说明；密钥页的旧版密钥状态缩短为「旧版密钥 · 无法签名」。不签名红字、签名状态、未核对联系人等警告保留。
- **修复**：Android 导入待解密文件的大小上限改按 NKEM v5（含原文件名记录）的容器开销计算，接近上限的签名文件不再无法导入。
- **依赖与构建**：kotlinx-serialization 1.13.0、Gradle 9.9.1、Robolectric 4.18、桥接库 `cc` 1.11.2；Android 设备测试更稳定；文档与 NKEM v5 的默认行为对齐。

### 兼容性与升级

- Android **6.0.0 / versionCode 18**，最低 API 26、目标 API 36，仅 arm64-v8a。沿用 v3.2.0/v3.3.0 签名，可直接覆盖升级。
- **5.2.0 及更早版本打不开 NKPR v3 私钥**：CLI 和桌面应用输入口令后报告「私钥密码错误或 NKPR 数据损坏」，Android 把它当作没有本机私钥，导入时拒绝。要把私钥交给 5.2 及更早版本，请先用「导出给 5.2 及更早版本的私钥」（CLI 为 `export-legacy-private-key`）导出副本。
- **升级后第一次解锁会把本机私钥改写为 NKPR v3**，之后回退到 5.2.0 将打不开本机私钥。升级前请备份公钥、加密私钥和口令；需要回退时，先在 6.0.0 中导出给 5.2 的私钥。
- 5.2.0 及更早版本导出的私钥（NKPR v1、v2）在 6.0.0 中需要按上文的方式导入；直接作为临时私钥或用 CLI 的其他路径打开会被拒绝。
- NKEM 文件容器不变：6.0.0 与 5.2.0 互相解密对方写出的 NKEM v3/v4/v5 文件，公钥和指纹不变。5.1.0 及更早版本打不开记录了原文件名的文件，4.x 及更早版本的限制与 5.2.0 相同。
- 未签名的 NKEM v3/v4 仍不认证发送者。NKEM 中的 AES-GCM 不提供密钥承诺性，NKEM v4/v5 由头部 HMAC-SHA512 承诺文件密钥。Argon2id 保持 64 MiB、3 次迭代、并行度 4。

### 平台与验证边界

- Windows 10/11 x64：CLI、GUI、MSI 和 EXE 安装程序均无 Authenticode 签名。保留本地固定 NTFS、私有 ACL 与路径检查。
- macOS Apple Silicon arm64：CLI 部署目标 11.0，原生 CI 基线 macOS 15；GUI 最低 macOS 13，使用 macOS 26 SDK 构建并在 macOS 26 上验证。不提供 Intel/Rosetta 构建。使用 ad-hoc 签名，没有 Developer ID 或 Apple 公证。
- Linux GUI：Ubuntu 24.04 构建，另在 Fedora 44 容器中安装并启动 RPM，在 Arch Linux 容器中构建并安装 Arch 包；需要 glibc 2.39+。DEB/RPM 依赖 Noto Sans CJK 字体和 `curl`（检查更新），便携包和 AppImage 需要系统自行安装。RPM 无开发者 GPG 签名。Flatpak 与 AppImage 在 CI 中安装并启动；X11 启动检查不代表所有发行版或 Wayland 实机。Flathub 与 AUR 尚未上架。静态 CLI 继续提供。

本项目仍是实验性工具，未经过独立专业安全审计，不应视为生产级软件或用于保护重要、敏感数据。

## English

### What's new

This release moves private keys to NKPR v3 with key commitment, and adds a Windows EXE installer, Linux AppImages and Flatpak bundles. Android and every CLI/GUI application are **6.0.0**; Core is **6.0**. The NKEM file formats and cryptographic parameters are unchanged.

- **Private keys in NKPR v3**: new and upgraded private keys are written as NKPR v3, which adds a 32-byte key commitment after the NKPR v2 salt, so a private key file opens under one password only. An NKPR v2 key keeps its keys, password, public key and fingerprint.
- **Older private keys only as your own key**: NKPR v1 and v2 have no key commitment, so someone can build a file that opens under several passwords and learn from your attempt whether yours is one of them. Each app therefore opens the older formats only for your own key: the app's key on Android, "My private key" in the desktop settings, and `keys/private.key.enc` in the CLI. Your own NKPR v2 key is rewritten as NKPR v3 in place after unlocking, with the same password.
- **Importing a key exported by an older version**: on Android, importing an older-format key explains the risk before asking for the password and opens the file only once you confirm it is your own key exported from an older NekoKEM; a 4.x NKPR v1 key can be upgraded to an identity key straight away, or imported as it is after a 3-second warning. In the desktop apps, **Upgrade key** on an older-format key other than "My private key" first shows a warning that can be confirmed only after three seconds, then rewrites the key as NKPR v3. Temporary private keys refuse older formats. The CLI opens an older key at any other path only with `--legacy-private-key`, and `upgrade-key` rewrites a key as NKPR v3.
- **Export private key for 5.2 and earlier**: the Android Keys page and the desktop apps (**For older versions → Private key for 5.2**) gain this action, and the CLI gains `export-legacy-private-key`. It writes an NKPR v2 copy under the same password for an older installation. On macOS the export can also save the password to the Keychain.
- **Windows EXE installer**: the new `NekoKEM-Windows-GUI.exe` installs the same app as the MSI with a double-click; its arguments go to `msiexec`, so `/quiet` installs silently.
- **Linux AppImage**: each architecture gains `NekoKEM-linux-<arch>-GUI.AppImage`, one file that runs after `chmod +x` without installing or root. It needs FUSE (`fusermount3`); without it, add `--appimage-extract-and-run`.
- **Flatpak**: each architecture gains a single-file bundle, `NekoKEM-linux-<arch>-GUI.flatpak` (app ID `io.github.shixiaoshi0417.NekoKEM`, Freedesktop 26.08 runtime). The sandbox grants no filesystem access: files, keys and the decryption folder are chosen in the desktop's file chooser (xdg-desktop-portal), and the app reaches only what was chosen.
- **Arch Linux**: the repository gains `linux/arch/PKGBUILD` (`nekokem-bin`), which repackages the released CLI and GUI folder archives for pacman on x86_64 and aarch64.
- **Release notes in the update prompt**: the Android and desktop update prompts include the new version's release notes, folded by default and scrolling within a fixed height when expanded, in the section matching the interface language.
- **Cleaner screens**: every app drops the explanatory small print that stayed on its pages, including the About introduction, the contacts and multi-select hints, the subtitles under settings switches, the notes under the legacy key export buttons, the fingerprint QR note and the password hint on the encrypt page; the Keys page shortens the legacy key status to "Legacy key · cannot sign". Warnings such as the unsigned-encryption notice, signature status and unverified contacts stay.
- **Fix**: the Android size limit for files imported for decryption now uses the NKEM v5 container overhead with the original-name record, so signed files close to the limit can be imported.
- **Dependencies and build**: kotlinx-serialization 1.13.0, Gradle 9.9.1, Robolectric 4.18 and the bridge's `cc` 1.11.2; steadier Android device tests; the documentation now matches the signed NKEM v5 defaults.

### Compatibility and upgrading

- Android **6.0.0 / versionCode 18**, minimum API 26, target API 36, arm64-v8a only. The v3.2.0/v3.3.0 signer is retained for in-place updates.
- **NekoKEM 5.2.0 and earlier cannot open an NKPR v3 private key**: the CLI and desktop apps report "Private-key password is incorrect or NKPR data is corrupted" after asking for the password, and the Android app treats it as no key on the device and refuses to import it. To move a key to 5.2 or earlier, first use "Export private key for 5.2 and earlier" (`export-legacy-private-key` in the CLI).
- **The first unlock after upgrading rewrites your own private key as NKPR v3**, and a 5.2.0 installation rolled back afterwards cannot open it. Back up the public key, the encrypted private key and its password before upgrading; to roll back, export the key for 5.2 from 6.0.0 first.
- Private keys exported by 5.2.0 and earlier (NKPR v1 and v2) are opened in 6.0.0 through the import described above; as a temporary key or at another CLI path they are refused.
- NKEM containers do not change: 6.0.0 and 5.2.0 decrypt each other's NKEM v3/v4/v5 files, and public keys and fingerprints stay the same. 5.1.0 and earlier cannot open a file that records its original name, and the limits of 4.x and earlier are the same as for 5.2.0.
- Unsigned NKEM v3/v4 still does not authenticate senders. AES-GCM in NKEM provides no key commitment; NKEM v4/v5 commit to the file key with the header HMAC-SHA512. Argon2id remains 64 MiB, three iterations, parallelism four.

### Platform and validation boundaries

- Windows 10/11 x64: the CLI, the GUI, the MSI and the EXE installer are not Authenticode signed. Local fixed NTFS, private ACL and path checks remain.
- macOS Apple Silicon arm64: the CLI has deployment target 11.0 and a native CI baseline of macOS 15; the GUI needs macOS 13 or newer and is built with the macOS 26 SDK and tested on macOS 26. No Intel/Rosetta builds. Signatures are ad hoc, without Developer ID or Apple notarization.
- Linux GUI: built on Ubuntu 24.04, with the RPM also installed and started in Fedora 44 containers and the Arch package built and installed in Arch Linux containers; requires glibc 2.39+. The DEB/RPM depend on Noto Sans CJK fonts and `curl` (for the update check); with the folder archive or the AppImage, install them yourself. RPMs are not developer-GPG-signed. CI installs and starts the Flatpak and the AppImage; X11 launch tests do not establish every distribution or physical Wayland session. NekoKEM is not yet on Flathub or the AUR. Static CLI packages remain available.

This remains an experimental tool without an independent professional security audit; it is not production-grade software and should not protect important or sensitive data.
