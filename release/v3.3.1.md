# NekoKEM v3.3.1

## 简体中文

### 本版更新

v3.3.1 新增 macOS Apple Silicon 和 Linux 原生桌面支持，Android 与所有 CLI/GUI 应用统一为 3.3.1，Core 保持 3.1。

- **M 系列 Mac**：新增原生 arm64 CLI、Terminal 菜单启动器，以及 Rust + Tauri 2 + Vue 3 + TypeScript GUI，提供 `.app` ZIP 和 DMG。GUI 使用系统 WKWebView；CLI 与 Linux 共用完整参数、五项菜单和语言目录。
- **Linux GUI**：同时提供 x86_64、aarch64 原生 DEB、RPM 和便携 TAR.GZ。安装包包含桌面菜单入口、现有方形图标和许可；RPM 声明共享库能力依赖，ARM64 包声明对应动态加载器依赖。便携包通过 `NekoKEM-GUI.sh` 启动，仍需系统 GTK3、WebKitGTK 4.1 和 glibc 2.39+。
- **桌面体验**：Mac/Linux 复用 Windows GUI 的五语言自动检测、原生文件选择、粘贴 PEM、进度、取消、键盘导航和遵循减少动态效果设置的动画。生产前端只加载本地内容，经受限接口调用共享 C17 Core。
- **文件安全适配**：macOS 检查所有者、私有权限、扩展 ACL、符号链接、硬链接和大小写/Unicode 名称别名；普通文件要求 `fsync` 与 `F_FULLFSYNC`，父目录要求 `fsync`。Linux GUI 沿用现有 POSIX 文件层，粘贴私钥暂存为受保护文件；失败、取消和未认证解密不提交输出。
- **构建与性能**：继续固定 OpenSSL 4.0.3 并校验官方源码 SHA-256，保留汇编加速、线程支持和编译加固。Linux GUI 静态链接 PIC libcrypto 并隐藏符号，避免影响 WebKit 的系统 TLS 库。64 KiB 流式处理与逐块取消检查保持不变。
- **安装包修复**：生成权限正确的公开图标/许可副本，不放宽原始文件或私钥权限；严格验证 DEB/RPM 资源、权限、依赖、摘要和包内校验和。修复原生窗口测试等待窗口管理器与可见窗口的时序。
- **工作流与文档**：继续只有 `CI` 和 `Release` 两个工作流。CI 构建并测试所有平台，包括 Android API 26/35、跨平台历史格式互操作，以及 Ubuntu 24.04 DEB 和同架构 Fedora 44 容器内 RPM 的非 root、保留沙箱的实际窗口启动/正常关闭。Release 只构建打包，保留依赖、二进制、签名和产物完整性检查。README 更新完整下载与安装说明。
- **图标**：Android 保留方形白底图案；Windows EXE 保留方形图案和外部透明区域；macOS ICNS/Linux PNG 复用现有图案；README 继续使用专用圆角展示图。

### Android 升级

Android 应用为 **3.3.1 / versionCode 6**，最低 API 26，目标 API 35，仅提供 arm64-v8a。**沿用 v3.2.0/v3.3.0 发布签名，可直接覆盖升级，无需卸载。** 建议先导出公钥和加密 NKPR 私钥，验证备份并保留私钥密码。

仅旧签名 v3.1.x 用户需要在备份验证后卸载重装；卸载会删除内部密钥与数据，没有可用私钥或忘记密码将无法恢复解密。指纹不能恢复密钥。历史签名迁移见 [v3.2.0](https://github.com/Shixiaoshi0417/NekoKEM/blob/main/release/v3.2.0.md)。

### 格式、安全边界与兼容性

- **Core 3.1、NKEM v3、NKPR v1 不变**。X448 + ML-KEM-1024、HKDF-SHA512、AES-256-GCM、header/AAD、KDF 输入与 domain、nonce/tag、指纹与 GCM 长度限制保持原有要求。NKEM v1/v2 不再支持。
- NKPR 仍使用 Argon2id **64 MiB、3 次迭代、并行度 4**，不降低密码成本；随机性、认证、敏感缓冲区清理和认证后提交规则保持不变。
- Windows 10/11 x64 保留本地固定 NTFS、所有者/ACL/可信父目录检查，以及网络、设备、ADS、重解析点拒绝。Windows CLI/GUI **没有 Authenticode 签名**；验证 Microsoft SDK loader 不代表应用已签名。GUI 需要 WebView2 Runtime。
- macOS 面向原生 M 系列 arm64，不提供 Intel/Rosetta 包。部署目标为 macOS 11.0，实际原生验证于 macOS 15；不等同于已验证 macOS 11.0 实机或每代芯片。包使用 **ad-hoc hardened-runtime 签名，没有 Developer ID 和 Apple 公证**，不能证明发布者身份或保证 Gatekeeper 放行。
- Linux GUI 构建基线为 Ubuntu 24.04，RPM 另在 Fedora 44 原生容器验证。需要 glibc 2.39+、GTK3 和 WebKitGTK 4.1；RPM 没有开发者 GPG 签名。X11 窗口检查不代表所有发行版或 Wayland 实机兼容。静态 Linux CLI 包继续提供。
- GUI 的 JavaScript/IPC 可能产生临时字符串副本，不能保证 WebView 堆可靠清零。成对文件提交不具备跨文件崩溃原子性；Windows 断电持久性、进程死亡、真实 SAF provider、并发修改和物理擦除仍有文档所述边界。不承诺跨系统或硬件性能相同。

本项目仍是实验性工具，**没有经过独立专业安全审计，不应视为生产级软件，不应用于保护重要或敏感数据**。

## English

### What's new

v3.3.1 adds native macOS Apple Silicon and Linux desktop support. Android and every CLI/GUI application are version 3.3.1; Core remains 3.1.

- **M-series Macs**: native arm64 CLI, Terminal menu launcher and Rust + Tauri 2 + Vue 3 + TypeScript GUI, distributed as an `.app` ZIP and DMG. The GUI uses system WKWebView; the CLI shares every Linux argument, the five-option menu and language catalog.
- **Linux GUI**: native x86_64 and aarch64 DEB, RPM and portable TAR.GZ packages. Installation packages include desktop menu entries, existing square icons and licenses. RPM declares shared-library capabilities, including the matching ARM64 dynamic loader. Portable packages launch through `NekoKEM-GUI.sh` and still require system GTK3, WebKitGTK 4.1 and glibc 2.39+.
- **Desktop experience**: Mac/Linux reuse the Windows GUI's five-language detection, native file dialogs, pasted PEM keys, progress, cancellation, keyboard navigation and reduced-motion-aware animations. Production loads local content only and calls the shared C17 Core through restricted interfaces.
- **Filesystem adaptation**: macOS checks ownership, private permissions, extended ACLs, symlinks, hard links and case/Unicode-equivalent path aliases. Regular files require `fsync` and `F_FULLFSYNC`; parent directories require `fsync`. Linux GUI retains the POSIX backend and protected pasted-key staging. Failure, cancellation and unauthenticated decryption do not commit output.
- **Builds and performance**: retain pinned OpenSSL 4.0.3 with official source SHA-256 verification, assembly acceleration, threading and compiler hardening. Linux GUI statically links PIC libcrypto with hidden symbols to avoid affecting WebKit's system TLS libraries. Streaming remains 64 KiB with cancellation checked for each chunk.
- **Package fixes**: create correctly permissioned public icon/license copies without broadening original or private-key permissions. Strictly verify DEB/RPM resources, permissions, dependencies, digests and internal checksums. Fix native window tests to wait for the window manager and visible application window.
- **Workflows and docs**: retain only `CI` and `Release`. CI builds and tests all platforms, including Android API 26/35, historical-format interoperability and actual non-root, sandboxed startup/normal-close checks for Ubuntu 24.04 DEB and native Fedora 44 container RPM installations. Release builds and packages only, retaining dependency, binary, signature and artifact integrity checks. READMEs now document all downloads and installation steps.
- **Icons**: Android retains its square white artwork. Windows EXEs retain the square artwork with transparent outer areas. macOS ICNS/Linux PNGs reuse the existing artwork; README keeps its dedicated rounded display image.

### Updating Android

Android is **3.3.1 / versionCode 6**, minimum API 26, targeting API 35, with arm64-v8a only. **The v3.2.0/v3.3.0 release signer is retained, allowing an in-place update without uninstalling.** Back up the public key and encrypted NKPR private key, verify those backups and retain the private-key password first.

Only old-signer v3.1.x installations need verified backups followed by uninstall/reinstall. Uninstalling deletes private keys and data; without a usable private key or its password, decryption cannot be recovered. Fingerprints cannot restore keys. Historical signing migration is documented in [v3.2.0](https://github.com/Shixiaoshi0417/NekoKEM/blob/main/release/v3.2.0.md).

### Formats, security boundaries and compatibility

- **Core 3.1, NKEM v3 and NKPR v1 are unchanged**. X448 + ML-KEM-1024, HKDF-SHA512, AES-256-GCM, headers/AAD, KDF inputs/domains, nonce/tag, fingerprints and GCM length limits retain their requirements. NKEM v1/v2 are no longer supported.
- NKPR still uses Argon2id with **64 MiB, 3 iterations and parallelism 4**, without reducing password cost. Randomness, authentication, sensitive-buffer cleanup and authenticated output commits retain their requirements.
- Windows 10/11 x64 retains local fixed NTFS, ownership/ACL/trusted-ancestor checks and rejection of network/device/ADS/reparse paths. Windows CLI/GUI are **not Authenticode signed**; verifying the Microsoft SDK loader does not sign the applications. The GUI requires WebView2 Runtime.
- macOS targets native M-series arm64, without Intel/Rosetta packages. The deployment target is macOS 11.0; native verification runs on macOS 15, not physical macOS 11.0 hardware or every chip generation. Packages use **ad-hoc hardened-runtime signatures without Developer ID or Apple notarization**, so they do not authenticate the publisher or guarantee Gatekeeper acceptance.
- Linux GUI builds use Ubuntu 24.04; RPM is additionally verified in native Fedora 44 containers. glibc 2.39+, GTK3 and WebKitGTK 4.1 are required. RPM is not developer GPG signed. X11 checks do not establish compatibility with every distribution or physical Wayland session. Static Linux CLI packages remain available.
- JavaScript/IPC may create temporary string copies, so reliable WebView heap zeroization is not guaranteed. Paired-file commits are not crash atomic across files. Windows power-loss durability, process death, real SAF providers, concurrent modification and physical erasure retain documented limits. Identical performance across systems or hardware is not promised.

This remains experimental software. **It has not undergone an independent professional security audit, must not be considered production-grade, and must not be used to protect important or sensitive data.**
